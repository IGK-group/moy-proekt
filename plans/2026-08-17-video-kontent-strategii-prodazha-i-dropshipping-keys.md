## Откуда взялась методология

Разобрали конкурентный Reels-ролик аккаунта `Dropship` (`instagram.com/reel/DcG2YKksGLv/`) полным техническим пайплайном - `yt-dlp` (скачивание + метаданные) → `ffmpeg` (покадровая раскадровка, детект склеек) → `whisper` (транскрипция голоса с таймкодами) → визуальный разбор кадров через мультимодальное чтение.

**Вывод разбора:** ролик - не единая съёмка, а сборка из 3 источников: чужой/сторонний высокодосмотровый хук (не по теме аккаунта, просто "оддли сатисфайинг" видео) + собственный скринкаст (реальная работа в бизнес-инструментах) + шаблонный монтаж CapCut (плотные склейки ~каждые 1.5-2 сек, авто-субтитры, готовые текстовые пресеты). CTA - не прямая ссылка, а призыв к комментарию (обходит алгоритмическое занижение охвата у постов со ссылкой в тексте).

Второй технический разбор ("как ролик делался") подтвердил: хук вероятно стоковый/сторонний (не связан с темой аккаунта), скринкаст - реальная запись экрана (QuickTime/iPad), текстовые оверлеи - готовые CapCut-пресеты ("keyword pop" стиль), не индивидуальная анимация.

Из этого шаблона выросли **две параллельные стратегии** вместо одной - см. ниже.

## Прогресс сборки (2026-08-18) - чекпоинт перед паузой

**Голос-шаблон записан и проверен.** 3 части на Google Drive `AI/голос/`, финальный текст - в `shopify-tools/настройка/голос-шаблон/README.md`. Товар по имени не называется - подтверждено анализом 4 роликов конкурента (везде идентификацию товара несёт видеоряд, не голос).

**Библиотека цен (300 файлов) была перепутана - исправлено через проверенный индекс.** 51 из 300 файлов не совпадали с названием (не единый сдвиг, смесь перестановок + один большой перепутанный блок ~115-164). Построен `reverse_index.json` (реальное число → правильный файл) - сохранён в `shopify-tools/настройка/голос-шаблон/`, использовать вместо названий файлов напрямую. 10 чисел отсутствуют физически: 157-164, 215, 275 - нужна досъёмка, если понадобятся именно эти цены.

**Собраны 2 черновика ролика (оба технически рабочие, но НЕ финальные - видео решено пересобирать заново):**
- `final_draft.mp4` (v1, 43.3 сек) - первая сборка, хук + 3 больших блока скринкаста, letterbox с чёрными полосами
- `final_v2.mp4` (v2, 34.1 сек) - после правки по фидбеку: темп речи был **102 слова/мин против 206 у эталона** (в 2 раза медленнее) - паузы срезаны через `ffmpeg silenceremove`; монтаж пересобран на 15 склеек по границам реплик (whisper-таймкоды) вместо 3 блоков; добавлено `Видео CJ.MOV` (раньше не использовалось); все склейки приведены к единому вертикальному формату 720×1280 без чёрных полос (crop-fill вместо letterbox)

Оба черновика загружены на Google Drive в `AI/контент дропшип/`. Исходники для сборки (сырые скринкасты, хук) лежат в Google Drive `AI/видео CJ/` и `shopify-tools/настройка/product-videos/` - если локальные временные файлы сессии не сохранятся, пересборка стартует оттуда, не с нуля.

**Технический рецепт сборки (чтобы не выводить заново):**
1. Скачать голос-шаблон (3 части) + нужные 2 цены по `reverse_index.json` → склеить в `ffmpeg` (`concat` demuxer) → одна голосовая дорожка
2. Срезать лишние паузы: `silenceremove=start_periods=1:start_silence=0.05:start_threshold=-30dB:stop_periods=-1:stop_silence=0.1:stop_threshold=-30dB:detection=peak`
3. Расшифровать итоговую дорожку через `whisper` (`--model small --language ru`) → получить точные тайминги каждой реплики
4. Скринкасты привести к единому формату: `scale=-2:1280,crop=720:1280,setsar=1,fps=24` (заполнение кадра, не подложка)
5. Нарезать источники по границам реплик (`trim`+`setpts`) и склеить (`concat`) под голосовую дорожку - меняя источник на каждой реплике для динамики
6. Приклеить хук в начало (со своим звуком) через `filter_complex concat` с приведением всех потоков к единым scale/fps/samplerate

**Открыто на момент паузы:** боль-бит хука (пункт 1 выше) всё ещё не выбран; hook-артефакты (пробел 4 в таблице аудита) не проверялись; следующая пересборка видео - по новым указаниям Гены, когда вернёмся к этой задаче.

Цены для озвучки: **закупка $50, продажа $170** (оба числа проверены по `reverse_index.json`, корректны). Голос пересобран с этими цифрами (`voice_vacuum_tight.wav`, 28.86 сек). Любой "средний" вариант (v4) неизбежно оставляет немного blur-полей сверху/снизу - это не баг, а геометрия, компромисс между "видно всё" и "заполняет кадр".

### Технический рецепт сборки (не выводить заново)

1. **Портретные исходники** (сняты вертикально, но хранятся с флагом поворота -90°): только `scale=720:1280,setsar=1,fps=24`. Кроп НЕ нужен - геометрия уже 9:16. **Важно:** автоповорот у ffmpeg 7.0 работает сам по себе только если НЕ добавлять свой `-vf` с crop/overlay - в таком случае он отключается, и нужно либо обойтись одним `scale` (тогда автоповорот срабатывает), либо явно проверять итоговые пиксельные размеры кадра перед тем, как писать кроп-математику.
2. **Лендшафтные исходники** (старые скринкасты 1920×1080, без флага поворота): blur-fill без потери контента - `crop=750:1080:850:0,split=2[fg][bgsrc];[bgsrc]scale=720:1280:force_original_aspect_ratio=increase,crop=720:1280,gblur=sigma=25,eq=brightness=-0.2[bgb];[fg]scale=720:-2[fgs];[bgb][fgs]overlay=(W-w)/2:(H-h)/2,fps=24`. Смещение кропа (850, не по центру) - чтобы не срезать руку с ручкой, которая обычно у правого края кадра.
3. **Срезка пауз голоса:** `silenceremove=start_periods=1:start_silence=0.05:start_threshold=-30dB:stop_periods=-1:stop_silence=0.06:stop_threshold=-30dB:detection=peak,atempo=1.12` - только срезка пауз + лёгкое ускорение темпа (без искажения тона).
3.1. **Обязательное правило (с 2026-08-18): выравнивать громкость всей склеенной дорожки.** Голос собирается из разных кусков (части шаблона + отдельно записанные цифры цен) - каждый кусок мог быть записан с разной громкостью. Последним шагом после срезки пауз - `loudnorm=I=-16:TP=-1.5:LRA=11` (EBU R128), затем пересэмплировать обратно в 48000 Hz (`loudnorm` меняет sample rate на выходе, это нужно поправить перед склейкой с видео: `-ar 48000 -ac 1`).

### Обновление 2026-08-18 (вечер) - ОБЯЗАТЕЛЬНЫЙ метод сборки видео: один проход, не четыре

**Проблема, которая была найдена:** старая схема сборки шла через 4 отдельных файла-пересжатия подряд (кроп/масштаб → склейка → zoompan → tpad) - каждый шаг это отдельный H.264-энкод, и потери резкости накапливались («generation loss», как пересохранить JPEG четыре раза подряд). Итог был заметно мутнее исходников с телефона.

**Новый обязательный метод - один `filter_complex`, один финальный энкод:**

1. **Канвас 1080×1920, не 720×1280.** Портретные исходники и так нативно 1080×1920 - даунскейл до 720 не нужен, только теряет резкость зря.
2. **Все операции (trim + crop/scale + concat + zoompan) - в одном filter_complex-графе, один вызов ffmpeg.** Не сохранять промежуточные файлы через отдельные вызовы `ffmpeg` - строить граф целиком в Python (список кортежей `(старт, конец, источник, оффсет, тип)` → сборка строки filter_complex → один `subprocess.run`).
3. **Портретные куски:** `scale=1080:1920:flags=lanczos,setsar=1,fps=24` - `lanczos` вместо дефолтного алгоритма даёт заметно чётче.
4. **Лендшафтные куски (blur-fill):** кроп расширен до `crop=900:1080:770:0` (было `750:1080:850:0`) - меньше апскейл переднего плана, значит меньше размытия от растяжения. Плюс `unsharp=5:5:0.8:5:5:0.4` на передний план отдельно.
5. **Лёгкая доводка резкости на весь ролик** - `unsharp=5:5:0.5:5:5:0.3` сразу после `zoompan` в том же графе.
6. **Кодирование:** `-c:v libx264 -preset slow -crf 14` для максимального качества (файл больше, ~17-18 Мбит/с, ~50 МБ на 25 сек) или `-crf 16` как разумный баланс (~9 Мбит/с, ~27 МБ) - платформы (Instagram/TikTok) всё равно пережмут при загрузке, выше определённого битрейта разница не видна зрителю.
7. **После zoompan длительность может уплыть на ~1 сек** (несовпадение fps между concat-выходом на 24fps и zoompan на 25fps) - **всегда проверять** итоговую длительность видео против длительности голосовой дорожки перед финальным миксом, при недостаче - увеличить `tpad=stop_mode=clone:stop_duration=X` (не жалеть паддинг, недостача обрезает КОНЕЦ фразы, это хуже, чем лишний статичный кадр).
8. **Финальный микс** - `-c:v copy -c:a aac -b:a 192k -shortest` (видеопоток уже в финальном качестве, не трогать повторным энкодом).

## Отдельный шаблон - товар БЕЗ материалов CJ/магазина (пример: рюкзак)

Не для каждого товара в ассортименте есть скринкаст CJ-таблицы или магазина - для части товаров есть только демо-видео от поставщика. Для такого случая - отдельная, более простая структура, зафиксирована 2026-08-18 на примере рюкзака-сумки (демо от поставщика, $10 закупка).

**Голос - 2 части + одна цена, без 4-частного шаблона:**
- Часть 1: интро + вопрос "Его цена?" (пример: «Смотри, какой классный товар я нашёл для дропшипинга. Его цена?»)
- **[Цена - закупка]**
- Часть 2: сравнение с конкурентом + наша цена + интеграция в магазин + реклама + ожидание продаж (пример: «У ближайшего конкурента его стоимость 45 долларов. Мы можем выставить этот товар за 40 долларов. Интегрируем его в свой магазин, запускаем рекламу 5 долларов в день и ждём продажи.»)

Голос для такого разового товара пишется сразу под конкретику (не универсальный шаблон), потому что нет данных из CJ-таблицы для генерализации - Гена диктует голосом сразу с нужными цифрами по памяти/расчёту.

**Видеоряд - когда нет CJ/магазин-скринкаста под товар:**
- **Все реплики про сам товар** (интро, вопрос цены, сравнение с конкурентом, наша цена) → демо-видео от поставщика, нарезанное на сегменты с сэмплированием по всей длине исходника (не зацикливать один и тот же момент - брать разные точки: начало, середина, конец демо).
- **"Интегрируем в магазин"** → нейтральный экран Shopify **без товаров в кадре** (страница выбора темы `Choose your store` - Horizon/Tinker/Savor - подтверждено, что там никогда не мелькают товары-роботы из другого потока). Не использовать `shopik_new.mov`/`magazin_new.mov` - там реальные роботы, не в тему для другого товара.
- **"Ждём продажи"** → `graph_new.mov` (график сессий), **всегда как последний кадр ролика**, если фраза про ожидание продаж - финальная в тексте.
- CJ-таблица и живой магазин **не используются вообще**, если под конкретный товар нет своих данных в CJ - не подставлять данные другого товара по умолчанию.
4. **Динамика на статичных скринкастах:** один непрерывный медленный зум на весь смонтированный ролик (после склейки, поверх всех склеек сразу) - `zoompan=z='min(zoom+0.0008,1.06)':d=1:x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':s=720x1280:fps=25`.
5. **Темп речи-эталон:** конкурент - ~206 слов/мин. Наша исходная запись была 102 слов/мин (в 2 раза медленнее) - после срезки пауз выходит на 150-160 слов/мин, достаточно.
6. **Темп монтажа-эталон:** конкурент режет каждые ~1.6 сек. Мы держим похожий темп - **кроме** непрерывных кусков про цены (см. правило ниже).

### Смыслы для масштабирования (правила, не завязанные на конкретный товар)

- **Одна цена - один непрерывный видеокусок.** Если голос называет несколько цифр подряд из ОДНОГО источника (напр. таблица CJ: закупка → доставка → итог) - видео тоже должно быть одним непрерывным куском без монтажных склеек внутри. Переключать источник ТОЛЬКО когда меняется смысловой контекст, не чаще.
- **Когда голос называет конкретный инструмент/действие ("через Higgsfield делаю ролик") - показывать именно его**, не абстрактную заглушку. Если под рукой есть буквально то, о чём говорится (наш собственный AI-ролик, наш реальный магазин) - использовать его, а не скринкаст "вообще".
- **Цифры в озвучке = цифры на экране в этот момент.** Перед тем как использовать число из библиотеки 1-300 - **всегда** скачать файл заново и прогнать через `whisper`, никогда не доверять ни названию файла, ни ранее сохранённому индексу (`reverse_index.json` устарел уже дважды за сессию - Гена дозаписывал/чинил отдельные номера, кэш не поспевал).
- **Снимать сразу вертикально.** Любой новый скринкаст, снятый в портретной ориентации 9:16, не требует кропа вообще - экономит целый этап монтажа и убирает риск "не видно что показываю". Лендшафтные записи (стол/ноутбук со стороны) - всегда компромисс между размером и потерей контента.
- **Cyrillic-имена файлов с пробелами часто ломают bash/ffmpeg** (несовпадение нормализации Unicode NFC/NFD между Google Drive и локальной ФС). Всегда копировать в ASCII-имя через `python3 os.listdir()+shutil.copy()` (сопоставление по regex на самой строке из listdir, не ручной ввод кириллицы в bash) прежде чем обрабатывать.
- **Система "1 голос + N хуков + N скринкастов"** воспроизводима на любой товар в ассортименте (DYP, Ultra-Thin) - меняются только: хук-видео, 3 цифры цены (из проверенной библиотеки), и при необходимости конкретная строка в CJ-таблице, на которую указывает рука.
