# MebelShop - навигация

Карта проекта. Читай в начале каждой сессии.

## Что это за проект

**MebelShop** - дропшиппинг-магазин, US/EU рынок, два потока (обновлено 2026-08-09):
- **Активный:** умные гаджеты для дома (window cleaning robot, robot vacuum) - закупка и логистика через CJdropshipping, AI-контент без живой съёмки.
- **На паузе:** мебель из Китая - живые видео с фабрик как УТП, отдельная стратегия, запуск позже.

Подробности - `business/INDEX.md`.

## Порядок чтения в начале любой сессии

1. `ai-clone/INDEX.md` - кто я и как думаю.
2. `business/INDEX.md` - что мы делаем (продукт, аудитория, экономика).
3. `CLAUDE.md` (этот файл) - правила репо, стек, навигация.
4. Зона задачи: нужный файл из `business/`, `plans/<актуальный план>`, `mastery/<область>`.

Слой 1 (клон) раньше слоя 2 (бизнес) не случайно: сначала **кто** думает, потом **о чём**.

## 8 правил репо

1. **Не хардкодить динамику** (цены, метрики, ссылки). Меняющиеся значения - через `business/life-metrics.md` с маркером **LIVE**.
2. **Не деплоить без явной команды.** Push в main = потенциальный авто-деплой.
3. **Удалять одноразовый код** после использования - в том же коммите.
4. **Большая фича = план в `plans/`.** Задача больше часа - нужен план.
5. **После каждой фичи - цикл из 5 ходов** (см. ниже). Без него фича не считается закрытой.
6. **`git add` поимённо.** Никогда `git add .` или `git add -A`.
7. **`.env` только через `process.env.НАЗВАНИЕ`** в коде. Файл целиком - никогда.
8. **Ищи в `prompts/INDEX.md`** до того как писать промпт с нуля.

## Большая фича = план в `plans/`

- Один план = одна фича. Если план есть - работаем с ним.
- Имя файла: `YYYY-MM-DD-название-фичи.md`.
- Делится на фазы. Каждая фаза: статус `[ ]` / `[WIP]` / `[x]`.
- В конце - итоговый блок: реализовано или нет, что осталось.
- Любой агент обязан актуализировать план после каждой сессии.

## Цикл из 5 ходов после каждой фичи

Прогоняй каждый раз. Без этого фича не считается сданной.

1. **Найди ошибки** в написанном коде -> докажи примером -> исправь.
2. **Что упустили** (граничный кейс, валидация, обработка ошибок) -> докажи.
3. **Это РЕАЛЬНО проблема нашего проекта?** Сверь с `business/` и `plans/`.
4. **Свежий взгляд после правок** - перечитай diff как будто видишь впервые.
5. **Security review.** Персональные данные + контент третьих лиц + отправка наружу = стоп и аудит.

## Любая ошибка -> правило в `ai-clone/feedback/`

Когда говорю «не так» или «больше так не делай» - оформи файл в `ai-clone/feedback/` по канону **Rule -> Why -> How to apply**.

В следующих сессиях `ai-clone/` читается первым - правило применится автоматически.

## Ретроспектива в конце сессии

`retrospectives/YYYY-MM-DD_HH-MM_краткое-описание.md` по шаблону `retrospectives/TEMPLATE.md`.

**Не ждать конца сессии, если он неочевиден (Telegram и подобные каналы).** Как только появился конкретный ценный результат (контакт, ссылка, решение, вывод) - сохранять сразу в файлы репозитория/память, в том же ходу. См. `ai-clone/feedback/2026-08-04-sohranyat-srazu-ne-zhdat-konca-sessii.md` - потеря контактов фабрик из Telegram-сессии произошла именно из-за ожидания "конца", которого не случилось.

## Динамические цифры -> `business/life-metrics.md`

Цифры в `business/` не пишутся напрямую - протухают. Вместо этого:
> Выручка за март: **LIVE** -> `life-metrics.md` / «Выручка за месяц»

Вопрос про цифры = сначала читать `life-metrics.md`, потом тянуть данные, потом отвечать.

## Безопасность

- **НЕ читать** `.env` целиком. Нужна переменная - `process.env.НАЗВАНИЕ` в коде.
- **НЕ выполнять** `rm -rf` без явного подтверждения. Показывать что будет удалено.
- **НЕ отправлять** токены и ключи наружу через curl/wget/POST.
- **НЕ устанавливать** скиллы/MCP без аудита (см. `prompts/setup/08-skills-install.md`).
- **Перед Bypass Permissions** - обязательный git-коммит.
