# Ретро: ценообразование по рынку + аудит магазина + починка доставки

**Дата:** 2026-08-15 09:00 (продолжение долгой сессии)
**Длительность:** ~3 часа
**План:** `plans/2026-08-09-cj-api-integration.md`, `plans/2026-08-11-brending-i-oformlenie-magazina.md`

---

## 1. Задача

Сравнить наши цены с рынком США (Amazon и другие площадки) по каждому товару, скорректировать при необходимости, детально пересчитать юнит-экономику, затем провести полный аудит магазина по разделам и дозаполнить пропуски.

## 2. Как решал

1. DataForSEO Merchant API (Amazon live-выдача) по 4 таргетированным запросам под конкретные характеристики наших товаров, отфильтровал сопоставимый ценовой класс (убрал premium multi-station роботы и дешёвые аксессуары-обманки).
2. Пользователь не поверил на слово ("я тебе не верб проверь") - перепроверил независимо: веб-поиск по конкретному ASIN (HUTT S7) подтвердил цену на нескольких Amazon-страницах, нашёл ту же модель на AliExpress ($149 - заводская цена без розничной наценки), кросс-проверил диапазоны на Walmart через отдельный поиск.
3. Вывод: DYP недооценён (медиана класса $229.99, бестселлер-ориентир HUTT S7 $269.99) - поднял с $249.99 до $269.99 через Shopify Admin API (`PUT /variants/{id}.json` по всем 3 вариантам). W17S/Jieshi/Ultra-Thin уже на рыночной медиане - не трогал.
4. При более детальном пересчёте экономики нашёл и исправил ошибку: весь день считал эквайринг по ставке Basic-плана (2.9%+30¢), а у магазина план **Advanced** с реальной ставкой **2.5%+30¢** - профит был занижен.
5. Впервые посчитал постоянные расходы (Shopify Advanced $399/мес, Higgsfield Plus ~$44/мес) - раньше юнит-экономика учитывала только переменные затраты на заказ. Нашёл, что Advanced-план не окупает себя экономией на эквайринге до оборота ~$147k/мес (~817 заказов) - при 0 текущих заказах предложил временный переход на Grow ($105/мес), пользователь согласился, но смена плана оказалась недоступна через API (только вручную в Admin, биллинговая операция).
6. Полный аудит магазина по разделам через API: `shop.json`, `policies`, `pages`, `custom_collections`, `shipping_zones` (устарел!) → пришлось переоткрыть через GraphQL `deliveryProfiles`, `markets`, `webhooks`, `oauth/access_scopes`.
7. Нашёл и исправил критичное: зона доставки International висела на carrier-calculated USPS/DHL (не работает для CJ-дропшиппинга из Китая) - удалил через `deliveryProfileUpdate`, поставил фиксированную Free Shipping по всему миру (согласовано с пользователем).
8. Создал 2 коллекции (Window Cleaning Robots, Robot Vacuums), загрузил favicon из брендбука.

## 4. Что можно было лучше

- Сразу проверять реальный тарифный план магазина (`shop.json` → `plan_name`) перед тем как считать эквайринг по дефолтной ставке 2.9% - сэкономило бы пересчёт задним числом.
- При первой проверке доставки не полагаться на пустой ответ REST `shipping_zones.json` - сразу перепроверять через GraphQL `deliveryProfiles`, старое REST-поле в этой версии API просто не отражает реальные данные (устарело, но не задокументировано явно как deprecated в ответе).

## 5. Как было / как стало

- **Было:** DYP $249.99 (недооценён), эквайринг считался по неверной ставке, постоянные расходы нигде не учитывались, международная доставка не работала (сломанный carrier-calculated расчёт), коллекций не было, favicon не было.
- **Стало:** DYP $269.99 (обоснованно, 3 источника), точный расчёт с реальной ставкой Advanced-плана, посчитана точка безубыточности по подпискам (4-6 заказов/мес), международный чек-аут работает (Free Shipping), 2 коллекции и favicon на месте.

## 6. Что не сработало

- Попытка 1: сменить план Shopify (Advanced→Grow) через `PUT shop.json` → `406`. Попытка 2: поискать endpoint для смены плана в целом → подтверждено веб-поиском, что публичного API для этого не существует, только ручная смена в Admin (биллинг требует явного подтверждения владельца).
- Попытка 1: починить `shipping_zones` через старый REST `PUT /shipping_zones/{id}.json` → `406` (эндпоинт для записи устарел). Попытка 2: GraphQL `deliveryProfileUpdate` с `methodDefinitionsToDelete` внутри `zonesToUpdate[].methodDefinitionsToDelete` → ошибка `Field is not defined on DeliveryLocationGroupZoneInput`. Попытка 3: интроспекция схемы (`__type(name: "DeliveryLocationGroupZoneInput")`) показала, что удаление методов - поле верхнего уровня `DeliveryProfileInput.methodDefinitionsToDelete`, не внутри zone-инпута → сработало.
- Попытка сменить название магазина через `PUT shop.json` с полем `name` → `406` без текста ошибки. Shopify заблокировал запись большинства shop-level полей в актуальных версиях Admin API - подтверждено дважды (для имени и в целом для биллинга).
