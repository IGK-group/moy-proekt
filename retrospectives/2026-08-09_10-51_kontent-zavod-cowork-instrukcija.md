# Ретро: инструкция по контент-заводу на Claude Cowork

**Дата:** 2026-08-09 10:51
**Длительность:** ~1.5 часа
**План:** нет отдельного плана - разовая задача синтеза инструкции

## 1. Задача

Создать в `content-factory/` папки «инструкции» и «материал», изучить сброшенные Геной материалы курса Георгия Ривера (Google Drive -> SKILL) и собрать из них рабочую инструкцию «как создавать контент-завод».

## 2. Как решал

1. Создал папки `content-factory/инструкции/` и `content-factory/материал/`.
2. Нашёл папку `SKILL` на Google Диске через `rclone lsd gdrive:` (Гена скинул скриншот проводника, без прямой ссылки - догадался проверить существующий rclone remote `gdrive`).
3. Скачал всю папку (`rclone copy`, 11 файлов, 40МБ) в `content-factory/материал/SKILL-source/`.
4. Распаковал 2 zip и 1 `.skill` (на деле тоже zip) через `python3 zipfile` - системный `unzip` падал на кириллических путях ("invalid zip file with overlapped components").
5. Извлёк текст: `python-docx` для .docx, `pdfplumber`/`pymupdf` для PDF, `plistlib` для 3 файлов `.webarchive` (macOS/Safari bplist-снимок страницы).
6. Наткнулся на баг: несколько файлов после распаковки были в NFD-юникоде (кириллица разложена на составные символы, например «й» = и + бревис), из-за чего Read/Bash не находили файл по видимо тому же имени. Починил массовой нормализацией в NFC через `unicodedata.normalize`.
7. Один PDF (`Gaid_Claude_Cowork_Georgii_Rivera.pdf`, гайд "33 способа Cowork") оказался с битой шрифтовой картой - текстовый слой извлекается в мусор независимо от библиотеки. OCR недоступен (нет `tesseract`, нет `sudo` для установки). Прочитал первые 2 страницы через рендер в PNG + прямое чтение изображений (Read поддерживает картинки).
8. 3 файла `.webarchive` (Yandex Docs) оказались бесполезны: содержимое документа Яндекс.Диск подгружает через JS/API уже после загрузки страницы, в статичном снимке - только пустая оболочка редактора (подтвердил через `plistlib` - в `WebMainResource` пусто, в `WebSubresources` только JS/CSS/шрифты Яндекса, ни одного намёка на текст документа).
9. Прочитал весь читаемый материал (10 skill-файлов контент-системы, антидетектор в 3 версиях, сторителлинг-корректор, транскрипт видео "Контент завод 2" - ключевой источник механики автоматизации через Cowork, гайд по безопасности аккаунта Claude, промты для каруселей).
10. Синтезировал `content-factory/инструкции/claude-cowork-kontent-zavod.md` - не копипаста, а переработка под MebelShop с явным разделением слоёв (этот материал = производство текста, существующий GeeLark-план = дистрибуция).
11. Вплёл в `CLAUDE.md` (дерево репо) и `content-factory/INDEX.md` (таблица файлов + диаграмма конвейера).
12. Добавил `content-factory/материал/` в `.gitignore` (55МБ бинарников - PDF/zip/webarchive - по аналогии с `taobao-tools/`/`uploads/`).

## 4. Что можно было лучше

- Сразу проверять `rclone lsd gdrive:` при упоминании скриншота Google Drive, а не ждать явной ссылки - сэкономило бы один цикл вопрос-ответ (в этот раз сообразил сам, но стоит закрепить как паттерн).
- NFD/NFC баг с именами файлов после распаковки zip - стоило сразу после любой распаковки кириллических архивов прогонять `unicodedata.normalize('NFC', ...)` по всем именам, а не натыкаться на ошибку и чинить постфактум.
- Не устанавливать зависимость от `tesseract`/`sudo` в моменте - изначально закладывать, что OCR может быть недоступен, и сразу планировать fallback через рендер-в-картинку + прямое чтение.

## 6. Что не сработало

- Попытка 1: распаковать кириллический zip через системный `unzip` → упал с "invalid zip file with overlapped components (possible zip bomb)" (ложное срабатывание на кириллических путях). Решение: `python3 -m zipfile`/`zipfile` модуль справился без проблем.
- Попытка 2: извлечь текст из `Gaid_Claude_Cowork_Georgii_Rivera.pdf` через `pdfplumber` → мусорные символы (битая шрифтовая ToUnicode-карта). Попытка 3: `pymupdf` (`fitz`) → та же мусорная строка (значит проблема в самом PDF, не в библиотеке). Решение: рендер страниц в PNG (`fitz` `get_pixmap`) + прямое чтение картинок через Read (OCR через `tesseract` недоступен - нет пакета и нет `sudo`).
- Попытка 4: прочитать `.webarchive` файлы через `plistlib` → `WebMainResource` содержит только пустую HTML-оболочку (Яндекс.Документы рендерят контент через JS после загрузки, в снимке его нет). Проверил `WebSubresources` - тоже только служебные JS/CSS/шрифты, ни одного текстового ресурса с содержимым документа. Дальше идти некуда без реального браузера с JS-движком, которого нет в инструментах.
