# Ретро: Таблица товаров для фабрики juesion (TMAPI/Apify/Excel)

**Дата:** 2026-07-25 17:40
**Длительность:** ~несколько часов (многосессионная задача, началась 2026-07-21)
**План:** без формального плана в `plans/` (стоило бы завести с самого начала - фича вышла явно больше часа)

---

## 1. Задача

Собрать для фабрики juesion (tmall-магазин) эксель-таблицу товаров (фото / название / артикул / цвета / размеры / остатки), чтобы фабрика проставила туда оптовые цены.

## 2. Как решал

TMAPI (`item_detail`) для данных по одному товару - работает стабильно весь путь. Список всего каталога магазина (704 товара) не удалось получить автоматически ни через TMAPI (`/shop/items*` - все три варианта сломаны глобально), ни через Apify (`shopCatalog` - тихо стопорится на 1-й странице во всех трёх режимах). Оба упираются в антибот-защиту Alibaba на глубокую пагинацию. В итоге пользователь сам прислал файл `ссылки.xlsx` (195 ссылок, 73 уникальных) - это оказалось быстрее и надёжнее любых автоматических попыток.

Собрано 80 товаров (217 строк с разбивкой по цветам) через `taobao-tools/build_detailed_table.py`: фото по цвету, перевод цвета на русский (Google Translate, бесплатно), эвристика на "фото похоже на таблицу размеров -> подставить главное фото".

## 4. Что можно было лучше

- Сразу спросить пользователя, нет ли у него/фабрики готового файла со ссылками или экспорта из личного кабинета продавца - вместо часов на OCR скриншотов и тестирование сломанных API списков магазина.
- Предупредить о риске блокировки аккаунта Taobao ДО того, как просить вручную копировать много ссылок подряд, а не после того, как аккаунт уже заблокировали.
- Перед тем как менять рабочий скрипт (добавление эвристики про таблицы размеров), тестировать на маленьком файле перед пересборкой всех 80 товаров - тогда баг с порчей Excel нашёлся бы за 1 итерацию, а не за 4.
- Не путать "остаток use quota" и "потрачено" при чтении цифр с чужого скриншота - дважды перепутал направление процента/остатка на балансе TMAPI, зря тревожил пользователя несуществующей нехваткой денег.

## 5. Как было / как стало

- **Было:** 0 товаров в структурированном виде, только ссылка на магазин.
- **Стало:** `taobao-tools/product_table_final.xlsx` - 80 товаров/217 строк, фото по цвету, размеры/остатки, готово к отправке фабрике на простановку цен.

## 6. Что не сработало

- Попытка 1: получить список магазина через TMAPI (`/shop/items`, `/shop/items/v3`, `/shop/items/v4`) → сломано глобально у TMAPI (подтверждено на их же примере из документации).
- Попытка 2: получить список магазина через Apify (`shopCatalog`, все 3 версии) → тихо останавливается на 1-й странице (25-30 товаров из 704), не паджинирует дальше.
- Попытка 3: прямой обход через внутренний AJAX страницы магазина (`asynSearch.htm`) → антибот Alibaba (`__baxia__` редирект на логин), отказался обходить дальше принципиально.
- Попытка 4: топ-ап баланса TMAPI как решение сломанного списка магазина → не помогло (баланс не был причиной), пользователь потратил реальные деньги ($39) на неверную гипотезу.
- Попытка 5: кэшировать один PIL.Image объект и сохранять его в несколько файлов для ускорения → сломало итоговый xlsx (не открывался в реальном Excel, хотя все программные проверки проходили) - см. [[feedback_openpyxl_image_reuse_corrupts_excel]].
